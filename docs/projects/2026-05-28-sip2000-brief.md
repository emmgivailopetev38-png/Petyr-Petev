**Дата:** 2026-05-28  
**Клиент:** „СИП — 2000" ЕООД, гр. Русе (обществени поръчки)  
**Носител:** ProMarketing LTD  
**Платформа:** ZOPEXPERT (https://zopexpert.vercel.app)

**Статус:** Draft за одобрение

---

## 1. Контекст

СИП 2000 е консултантска фирма по ЗОП с 10+ години опит. Работят с няколко вида процедури (храни, строителство, надзор, услуги, доставки, рамкови) и текущо изпитват познати проблеми с general-purpose AI: загубени файлове, контекстни смесвания, липса на специализация, повтарящи се човешки грешки.

Собственикът на СИП 2000 иска:

1. **Специализирани AI агенти** (не generic чатове) по тип на процедурата
2. **Стъпкови протоколи** (do 1 → do 2 → audit → continue), не свободни разговори
3. **Quality-control агент** в края на веригата
4. **Постоянна памет** на това, което работи (knowledge accumulation)
5. **Daily auto-monitor** на всички нови обществени поръчки с draft жалби сутрин
6. **Видимост** на изпълнението — да наблюдава, не да чете финал
7. **Bulgarian-first** — терминология, формати, ЗОП специфика

Текущо ZOPEXPERT решава: чат памет, файлове, history, login, deploy. Това **е основата**. Надграждаме я.

## 2. Технически constraint-и

**Hermes през OpenAI-compatible API:**
- ✅ Streaming text completions работят
- ✅ Server-side файлова extraction (PDF/Word/Excel) работи
- ❌ Native tool calls не работят (`/v1/chat/completions` с tools връща празен content)
- ❌ Native agent loops с multi-step reasoning не са достъпни

**Извод:** „Tool use" реализираме **в Vercel** (server-side orchestration), не в Hermes. Hermes остава gen-1 LLM който приема контекст и връща текст. Това е напълно достатъчно — просто различен design pattern.

**Без external API (Claude/GPT):** за сега. Cloud (Claude API) се добавя в Phase 4 ако трябва по-силен модел за audit.

## 4. Phased план

### Phase 1: Specialized Workspaces (3-5 дни)

**Минимална жизнеспособна персонализация за СИП 2000.**

- Замяна на 6 generic чата с 6 специализирани workspaces
- Per-workspace системен prompt с ЗОП контекст за вертикала
- Welcome message с примерни запитвания
- DB колона `chats.system_prompt`, `chats.title`, `chats.welcome_message`, `chats.icon`
- UI промени: workspace избор от sidebar или header, custom welcome, иконки
- Файлова работа (Phase 0 ✅) и история (✅) се запазват както са

**Резултат:** клиентът отваря Workspace „Строителство" → Hermes автоматично е „в роля" → ползва ЗОП-специфични знания за строителство → дава фокусирани отговори. Все още няма playbooks.

### Phase 2: Playbook Executor (5-7 дни)

**Workflows като JSON.**

- Нова таблица `playbooks` (id, workspace_id, name, steps JSONB)
- `playbook_runs` за tracking (id, playbook_id, current_step, state, outputs)
- Server-side executor: всеки run преминава през стъпки, всяка стъпка е отделен Hermes call
- UI: live progress bar, видима текуща стъпка, pause/resume
- Първи playbooks (примерно):
  - „Изготви оферта за строителна процедура" (10 стъпки)
  - „Провери ЕЕДОП за коректност" (6 стъпки)
  - „Драфтирай жалба към КЗК" (8 стъпки)

**Резултат:** клиентът натиска „Стартирай playbook → Подготовка на оферта", вижда live execution, одобрява финалния output.

### Phase 3: Auditor + Knowledge (7-10 дни)

**Audit gate + RAG.**

- `knowledge_chunks` таблица (pgvector)
- Embedding pipeline: chunked документи → vectors → Supabase
- Initial seed: 100 КЗК решения + 20 шаблона + експертни бележки
- Auditor агент: отделен системен prompt, чете output на изпълнител агент, връща pass/fail + забележки
- UI: показва кои knowledge chunks са използвани (sources panel)

**Резултат:** като клиентът пита „Има ли практика по този казус", Hermes намира релевантни КЗК решения, цитира ги в отговора. Audit агент филтрира преди човешко ревю.

### Phase 4: Daily Monitor (7-10 дни)

**Cron job + email брифинг.**

- Vercel Cron / външен scheduler
- Scraper за aop.bg + ЦАИС ЕОП
- Per-поръчка анализ от Auditor агент
- Draft жалби генерация
- Email брифинг сутрин 07:00 + dashboard

**Резултат:** собственикът отваря мейла си сутрин и вижда списък „12 нови процедури днес, 3 високорискови, 1 готова жалба за подаване".

### Phase 5 (опционално): Cloud upgrade

Ако audit и daily monitor покажат, че Hermes допуска критични грешки на сложни казуси:
- Добавя се Claude API като опция за Auditor агент
- Hermes остава за изпълнение (генериране на текст)
- Claude само за висок-стейк ревизии

## 5. Промени в база данни

### Phase 1

```sql
alter table chats add column if not exists system_prompt text;
alter table chats add column if not exists welcome_message text;
alter table chats add column if not exists icon text;
alter table chats add column if not exists vertical text;
-- vertical = 'food' | 'construction' | 'supervision' | 'deliveries' | 'services' | 'framework'

-- Seed 6-те slots с СИП 2000 specific конфигурация:
update chats set
  title = 'Храни и хранителни продукти',
  vertical = 'food',
  icon = '🍎',
  welcome_message = 'Готов съм да работя по обществени поръчки за храни. Качи документация или ме питай за специфики по ЗОП и ППЗОП.',
  system_prompt = '<system prompt for food procurement>'
where slot = 1;
-- ... и т.н. за останалите 5
```

### Phase 2

```sql
create table playbooks (
  id uuid primary key default gen_random_uuid(),
  workspace_id uuid references chats(id),
  name text not null,
  description text,
  steps jsonb not null,  -- [{id, name, prompt_template, validation, ...}]
  created_at timestamptz default now()
);

create table playbook_runs (
  id uuid primary key default gen_random_uuid(),
  playbook_id uuid references playbooks(id),
  chat_id uuid references chats(id),
  state text check (state in ('running','paused','completed','failed')),
  current_step int,
  outputs jsonb default '{}',
  created_at timestamptz default now(),
  completed_at timestamptz
);
```

### Phase 3

```sql
create extension if not exists vector;

create table knowledge_chunks (
  id uuid primary key default gen_random_uuid(),
  workspace_id uuid references chats(id),
  source text not null,           -- e.g. 'КЗК Решение №...'
  chunk text not null,
  embedding vector(1536),
  metadata jsonb default '{}'
);

create index knowledge_chunks_embedding_idx
  on knowledge_chunks using hnsw (embedding vector_cosine_ops);
```

## 8. Phase 1 — детайлно (готово за изпълнение)

### 8.1 Цели

1. 6-те текущи чата стават специализирани workspaces за СИП 2000
2. Hermes автоматично знае ролята си в зависимост от workspace
3. Empty state и welcome message са релевантни на вертикала
4. Иконки за визуална диференциация
5. Файлова работа (текущо) се запазва — Hermes ще получава файлове в контекста на вертикалния prompt

### 8.2 Системни prompts по вертикал (примерни, ще се refine-нат)

**Храни (Workspace 1):**
```
Ти си експерт-консултант по обществени поръчки за храни и хранителни продукти 
в България. Работиш съгласно ЗОП и ППЗОП. Знаеш специфичните изисквания за:
- БДС стандарти за хранителни продукти
- Изисквания за хладилна верига и транспорт
- Срокове на годност в спецификациите
- Сертификати за хранителна безопасност (HACCP, ISO 22000)
- Аналози по ред 6.1 и 6.2 от Приложение 4 към ЗОП

Когато получиш документация, първо я класифицираш (открита/публично състезание/
покана), после идентифицираш ключови параметри (количества, срокове, гаранции).

Отговаряш на български професионален език. При неяснота молиш за уточнение,
не познаваш. Цитираш конкретни членове на ЗОП когато е приложимо.
```

**Строителство (Workspace 2):**
```
Ти си експерт-консултант по обществени поръчки за строителство в България...
[similar с фокус на ЗУТ, FIDIC договори, КСС, гаранции 4%/3%, аналози, и т.н.]
```

(И т.н. за останалите 4 — детайлно се пишат в Phase 1 изпълнение)

### 8.3 Технически промени (overview)

- **DB migration** `003_workspaces.sql` (Supabase Dashboard)
- **lib/types.ts**: разширява `Chat` тип с `system_prompt`, `welcome_message`, `icon`, `vertical`
- **app/api/hermes/chat/route.ts**: добавя workspace системен prompt в началото на messages array
- **components/ChatPanel.tsx**: показва icon + welcome message + специализиран placeholder
- **app/page.tsx**: server fetch включва новите колони

### 8.4 Времева оценка

- Системни prompts (6 × ~30 мин брейнсторм/писане) = 3 ч
- DB миграция + seed = 1 ч
- Type updates = 30 мин
- Hermes route модификация = 1 ч
- UI промени = 2 ч
- Тестове + deploy = 1 ч

**Общо: ~8.5 часа работа, 1 ден реално с тестове + ревизии = 2 дни.**

### 8.5 Acceptance criteria

- [ ] При отваряне на Workspace „Строителство" се вижда 🏗️ иконка и welcome message за строителство
- [ ] Hermes отговаря в роля на строителен експерт без да му казвам „ти си експерт по..."
- [ ] При въпрос „каква е гаранцията за изпълнение?" дава 4% (или 3% за <70k EUR), не общо обяснение
- [ ] При качване на PDF, Hermes го анализира през призмата на вертикала
- [ ] 6-те workspaces показват различни prompts и поведение
- [ ] Тестовете минават, deploy чист
